# AI model datasets

`events_train.csv` is a reproducible synthetic classroom dataset, generated by
`generate_demo_dataset.py`. Its risk labels describe illustrative scenarios;
they are not verified ground truth, real attack telemetry, or a measure of
real-world detection performance.

For a public-data experiment, this project supports a manually labeled subset of the
[DARPA OpTC eCAR release](https://github.com/FiveDirections/OpTC-data).
The release is public domain, but is roughly 1 TB and contains Windows
endpoint telemetry; do not commit the raw release or derived large files.

Regenerate the demo dataset from the project root:

```bash
python -m ai.generate_demo_dataset
```

By default this writes 900 rows (300 per class) to `ai/events_train.csv`, with
a fixed random seed so the file is reproducible. Each row has a
`data_origin=synthetic_scenario` column. The model training script ignores
this provenance column, uses stratified train/test splitting, and prints a
warning that the resulting metrics do not estimate real-world detection
performance.

## Prepare a bounded OpTC subset

Download only a small eCAR subset from the
[official data release](https://github.com/FiveDirections/OpTC-data), then
convert the selected records to newline-delimited JSON (one eCAR object per
line). For a source file that is a JSON array, `jq` can select process and file
events while producing JSONL:

```bash
jq -c '.[] | select(
  (.object == "PROCESS" and (.action == "CREATE" or .action == "START")) or
  (.object == "FILE" and
    (.action == "CREATE" or .action == "DELETE" or .action == "MODIFY" or
     .action == "UPDATE" or .action == "WRITE"))
)' optc-events.json > ai/data/optc_subset.jsonl
```

For newline-delimited source records, remove `.[] |` from the filter:

```bash
jq -c 'select(
  (.object == "PROCESS" and (.action == "CREATE" or .action == "START")) or
  (.object == "FILE" and
    (.action == "CREATE" or .action == "DELETE" or .action == "MODIFY" or
     .action == "UPDATE" or .action == "WRITE"))
)' optc-events.jsonl > ai/data/optc_subset.jsonl
```

Create `ai/data/labels.csv` with the event IDs that you have verified against
the release's ground-truth material. Use explicit labels; the preparation
script does not infer maliciousness from event names or timestamps:

```csv
id,risk_lvl
EVENT_ID_VERIFIED_AS_BENIGN,Normal
EVENT_ID_VERIFIED_AS_MALICIOUS,High Risk
```

Replace these example IDs with actual event IDs verified from the dataset;
they are illustrative placeholders, not OpTC records.

`risk_lvl` must be `Normal`, `Suspicious`, or `High Risk`. The dataset's
ground truth may support benign-versus-malicious labels but does not itself
define a `Suspicious` class. Only use `Suspicious` where an event was
independently labeled that way; otherwise train with the labels actually
available.

Prepare and train from the project root:

```bash
python -m ai.prepare_optc \
  --events ai/data/optc_subset.jsonl \
  --labels ai/data/labels.csv \
  --output ai/optc_labeled.csv

python -m ai.train_optc_model \
  --dataset ai/optc_labeled.csv
```

The trainer evaluates on hosts held out from training to reduce event-level
leakage. It requires every class to occur on at least two hosts and in both
the training and evaluation split; if that is not true, add more labeled
hosts rather than weakening the split. The trained artifact is written to
`ai/threat_model_optc.pkl` and takes precedence over the legacy synthetic
model after restarting the backend. Remove that artifact and restart the
backend to return to the original model.

The OpTC model uses only event type, process/file name, and parent-process
presence because those fields can be extracted from eCAR and supplied by this
application. OpTC does not provide the CPU and memory measurements used by
the legacy synthetic model. Since OpTC is Windows telemetry and this monitor
is macOS-first, its evaluation does not establish accuracy on macOS events or
production systems.
